# 公民科技知識庫：人機協同寫作 pipeline

這是「臺灣公民科技專案與工具行動指引」專案的人機協同寫作 pipeline，包含一套可複製的寫作流程（skill）、兩種文體的模板與範例。目標是降低「把知識整理成系統化文章」的門檻，讓社群貢獻者能照著流程，與 AI 協作產出格式一致、事實可查證、對 AI 檢索友善的公民科技文章。

## 內容物

```
civic-tech-writing-pipeline/
├── SKILL.md          寫作流程本體：文章類型、階段門檻、事實查核關卡、格式規範
├── templates/        兩種文體的模板（方法論長文、領域資源短文）
├── examples/         實際範例文章（陸續加入）
└── styles/           個人風格檔的說明與模板（風格可替換，流程共用）

docs/
└── 協作寫文章經驗回顧.md   這套流程的起源：第一次協作的逐輪紀錄與失敗案例
```

## 這套流程從哪裡來

`SKILL.md` 的規則不是憑空設計的，是從一次實際協作裡撞出來的。
[`docs/協作寫文章經驗回顧.md`](docs/協作寫文章經驗回顧.md) 記錄了那次過程：13 輪修改、6 個流程缺陷，
以及 3 個 AI 犯下的事實錯誤（金額被誤掛給錯的專案、風險清單被誤指為某機關自己的報告、
一個**杜撰的中文譯名**）。

現在 SKILL.md 裡的「開始前必問」、「譯名絕不自創」、「四類最容易出錯的情況強制降級」、
「從頭重寫比修改有效」，每一條都能在那份回顧裡找到它對應的那次犯錯。

想知道某條規則為什麼存在、或想判斷它在你的情境該不該調整，先讀它。

## 怎麼使用

**在 Claude Code**：把 `civic-tech-writing-pipeline/` 資料夾複製到 `~/.claude/skills/`，之後提到「寫方法論文章」、「整理資源清單」等需求時會自動觸發。

**在 claude.ai 網頁版**：把 `SKILL.md` 的內容（或本 repo 的 raw 連結）貼進對話，再開始寫作。

**在其他 AI 工具（ChatGPT、Gemini 等）**：本 pipeline 的所有檔案都是純 Markdown，任何 AI 都讀得懂，流程與查核清單本身是工具中立的。載入方式：

- **ChatGPT**：單次使用把 `SKILL.md` 與所選模板貼進對話；重複使用可建立 Custom GPT，把 `SKILL.md` 與 `templates/` 的檔案上傳為知識檔，指示欄寫明「依 SKILL.md 的流程與查核關卡協作寫文章」
- **Gemini**：作法相同，可貼進對話，或建立 Gem 並上傳檔案

跨工具使用注意兩件事：

1. 其他工具沒有 Claude 的技能自動觸發機制，每次開始要明確指示「照這份流程進行」
2. 流程中兩個環節依賴 AI 的工具能力：「讀後憑證」需要 AI 能實際連網讀取來源；「範圍型陳述的資料層抽驗」需要 AI 能下載檔案並執行程式。若你使用的工具做不到，依據等級規則會自動把這類陳述留在需人工處理的等級（★★★☆☆ 以下），由人補做該項查核，流程不會因此失效，只是人工介入的項目變多

**人與 AI 的分工**：人負責選題、提供素材、事實查核的最終把關與風格品味；AI 負責素材整理、大綱、初稿與格式查核。詳見 `SKILL.md`。

本 pipeline 以在 Claude 環境順暢運作為標準，不保證在其他 AI 工具上的使用體驗。
