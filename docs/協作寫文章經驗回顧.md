# 協作寫文章經驗回顧

> 本文件目的：蒸餾一次人與 AI 協作寫作的完整過程，供未來對話參考。
> 文章主題：英、美兩國嘗試將 AI 導入國會，降低重複作業（共三案例）
> 日期：2026-06-10

---

## 一、背景與目標

**文章用途**  
分析英美議會如何使用 AI 工具輔助幕僚作業，供讀者（含公部門工作者）了解他山之石。作者（Claire）計畫舉辦相關工作坊，本文章是研究素材整理。

**硬規範**
- 所有事實必須有可查證的來源
- 每次交付文章草稿，都要附資料來源（標題＋連結）
- 不杜撰、不猜測未經查證的資訊

**使用工具**
- civic-tech-writing skill（7 個寫作階段）

**作者寫作風格關鍵字（從範文萃取）**
- 對比式標題（如「不是 XX，而是 OO」）
- 口語化小標（以問題或場景帶入）
- 第一人稱誠實語氣（承認限制、疑問）
- 先拋出「眼前的問題」，再帶出工具是怎麼回應的
- 結尾開放性問句，留讀者思考空間
- 不說教，不鋪排大道理

## 三、流程仍可改善之處

**1. 太晚進入「精修」階段**  
R3 交出的草稿沒有套用 skill 的語氣要求，等於跳過了 Stage 6（語氣潤稿）。應在交付前先過一遍 skill checklist，不需要你指出才做。

**2. 應在開始前要求風格範文**  
直到 R5 才拿到你的 LawTrace 文章作為風格參考，若 R1 就讀範文，後面幾輪的語氣修改可以省去。建議流程：開始寫作前主動問「請提供一篇你滿意的範文」。

**3. 事實錯誤靠你揪，不夠**  
- 540 萬美元的 LOC 企業級 AI 平台被誤掛在 FixIt+ 名下（R6，你讀 FedScoop 原文後糾正）
- Defra 的風險清單被誤屬為 Defra 自己的報告（R6，你提問後查出是跨國研究）
- 「事務官辦公室」是杜撰的譯名（R8，你提問後查無根據）
- **改善方向**：寫完一個 section 後應主動列出「我有幾成把握」的聲明，不確定的主動標出待查。

**4. 格式規範是被動補上的**  
全形標點、不用破折號、專有名詞加括號解釋——都是被你糾正後才加入 skill，理想情況是預設就做。已更新 skill 規則。

**5. 素材一開始放太寬**  
初期把太多不直接相關的文章列入，導致大綱方向要幾輪才收斂。建議：Stage 1 就明確說「我把這篇文章的素材限定為…」

**6. 開頭應一次打包提問**  
許多問題（風格偏好、篇幅限制、發布方式、讀者設定）是分散在不同輪次才確認，造成中途調整。理想是開頭一口氣問清楚。

## 四、蒸餾成 skill／prompt 的素材

### 寫作開始前必問的 5 件事
1. 目標讀者是誰？（一般讀者、政府工作者、研究者……）
2. 有沒有可參考的範文？（風格對齊用）
3. 發布平台？（影響字數、標題風格、連結格式）
4. 有沒有需要完全避開或必須包含的內容？
5. 這篇文章要讀者做到什麼？（只是了解 / 思考 / 行動）

### Claire 的文風特徵
- 標題：對比格式（「不是 XX，而是 OO」）或場景式問題
- 小標：用場景或問題帶入，不用正式論文式標題
- 開頭：先拋出一個「眼前的問題或矛盾」，讓讀者認同，再帶出文章要解決的事
- 語氣：第一人稱誠實，承認自己不確定的部分；不說教
- 結尾：開放性問句，讓讀者帶著問題離開，不用大結論收束
- 連結：用超連結讓讀者可以自行查原文，不是裝飾

### 寫作交付前的查核清單
- [ ] 每個具體事實（數字、機構名稱、功能描述）都有對應來源嗎？
- [ ] 有沒有把「不同來源的資訊」混在同一個句子裡說成同一件事？
- [ ] 有沒有把「推測」寫成「事實」？
- [ ] 專有名詞第一次出現時有括號說明嗎？
- [ ] 全形標點符號（，。、？！：；「」）？
- [ ] 沒有破折號（——）？
- [ ] 語氣讀起來自然，不像報告？

### 階段門檻（簡化版）
1. 讀完素材，確認哪些資訊可用
2. 提出大綱（含每節主旨），**等確認後**再寫
3. 寫初稿，標出每個事實的來源
4. 查證不確定項目
5. 套用風格（參考範文），**從頭重寫**比修改有效
6. 交付：文章 + 資料來源清單

### 這次蒸餾出的更大命題
人＋AI 協作產出知識，可能是一套可複製的流程：
- 人負責：問題設定、風格品味、事實查核、讀者判斷
- AI 負責：素材整理、大綱結構、初稿、格式查核
- 邊界是移動的：這次 AI 提出了我沒想到的案例（Warwickshire），但也搞錯了兩個事實

這不是「AI 幫人寫作」，也不是「人監督 AI」，而是一種有來有往的知識協作——這個過程本身，可能就是值得記錄和分享的 insight。
