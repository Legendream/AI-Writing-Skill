## 發現 1：規則提案沒有搬運機制，會靜靜蒸發

| | |
|---|---|
| **現象** | 2026-08-07 的獨立驗收找出一條高價值規則：「資源網站的 `/about` 是必讀素材，不能只讀首頁」。這篇短文最嚴重的兩個錯誤（台南市議會觀測站的屆期範圍、未收錄提案）證據全在 `/about`。當時的查核總表第六節完整記下了這條建議，寫明「值得寫成規則提案放 `AI Writing Pipeline/docs/`」 |
| **證據** | 2026-08-09 對整個 skill repo 執行 `grep -rn "about\b\|關於本站\|說明頁" SKILL.md templates/ checklists/ docs/`，**零筆結果**。這條規則躺在文章 repo 的查核總表裡兩天，從未流進 skill |
| **為什麼漏得過去** | `checklists/README.md`「收到結果之後」只寫了一句話：「skill 沒防住的類型 → 寫成規則提案放 `docs/`」。這是建議，不是機制——沒有任何檢查點問「這篇交付時，上次驗收找到的規則提案搬了沒」 |
| **嚴重度** | **高**。這個漏洞是通用的，每篇文章的驗收都可能產生規則提案，沒有牙齒的話，**所有未來的發現都會走同一條路蒸發** |
| **提案** | 把搬運綁進「交付」的完成定義：查核總表固定新增一節「本篇產生的 skill 規則提案」，每項標明狀態（未搬運／已開 PR／已併入），且**該節所有項目狀態都不是「未搬運」才算交付完成** |
| **狀態** | ⏳ 待處理，另開 PR A |

## 發現 2：發布後驗證沒有交付物，跟關鍵詞實測是同一種失效

| | |
|---|---|
| **現象** | 這篇文章發布時，HackMD 網址用的是裸筆記 ID（`g0v.hackmd.io/<noteId>`），實測帶 `x-robots-tag: noindex, nofollow`，不會被搜尋引擎索引。這個問題只在 Claire 主動貼連結、AI 主動用 curl 查標頭時才被發現 |
| **證據** | 兩份驗收條件裡跟發布相關的四條（類型 A 第 49、50 條，類型 B 第 51、52 條）字面上就寫著「這件事無法從檔案本身驗證，是發布時的提醒，**驗收時口頭確認即可**」——沒有交付物、沒有留下任何痕跡 |
| **為什麼漏得過去** | 這與 PR #10（`keyword-research-deliverable`）修的漏洞是同一個病灶：**規則存在但沒有交付物的規則，等同沒有規則**。§2-1 關鍵詞實測當時就是這樣被跳過的，且完全沒被任何機制發現，直到使用者自己問起 |
| **嚴重度** | **高，且會重複發生**。跟發現 1 一樣是通用漏洞，不是這篇獨有 |
| **提案** | `發布指引.md` 新增「發布後回填」一節：實測結果存成 `_驗收紀錄/<篇名>_發布後驗證.md`，含各平台正式網址、三門檻逐項實測結果、正本指定。兩份驗收條件的四條改為指向這份交付物，不再是「口頭確認即可」 |
| **狀態** | ⏳ 待處理，另開 PR B |

## 發現 3：repo 定稿檔與發布版之間，沒有「誰是正本、何時回寫」的規則

| | |
|---|---|
| **現象** | 這次同時出現三處 repo 與發布版不一致：(1) 延伸閱讀計數，repo 的 `v.3.md` 寫「2 篇」，但正文已有 3 條連結，HackMD／Medium 發布版同樣先錯後改；(2) Medium 正文的「主題標籤：」那行停在舊版標籤，跟 Medium 頁面自己的標籤晶片（已更新）不一致；(3) repo 檔的標題／章節標題帶有 Google Docs 匯出殘留的 `**粗體**` 包裹，發布版上架時已被清掉，但 repo 檔沒跟著更新 |
| **證據** | `diff` repo 裡的 `v.3.md` 與 HackMD 用 `/download` 端點抓回的原始碼，差異涵蓋上述三項，另外還有標題階層（`##`／`###` 升級為 `#`）與 frontmatter 完全消失 |
| **為什麼漏得過去** | `SKILL.md` §7「修訂既有文章」的連動檢查假設改動發生在 repo 檔案裡（要求「全文搜尋舊值」），但這次的實際流程是 **repo → Google Docs → 平台**，最後一次修改發生在平台介面上，repo 檔完全不知情。`發布指引.md` 第七節的「指定正本」處理的是平台之間的 `rel=canonical`，沒有處理 **repo 與平台之間**的正本問題 |
| **嚴重度** | **中**。這次靠人工發現並用平台原始碼覆蓋 repo 檔解決，但沒有規則的話，下次同樣的落差不會被主動檢查 |
| **提案** | 明訂：發布前 repo 是正本；**發布後平台是正本，repo 檔必須回寫**。具體招式：HackMD 用 `<網址>/download` 端點取得原始 Markdown 直接覆蓋；Medium 沒有等價端點，需人工比對計數、標籤、標題三處 |
| **狀態** | ⏳ 待處理，另開 PR B（與發現 2 同一份文件的不同小節） |

## 發現 4：模板兩條規則互相矛盾——資源清單 4-8 個 vs 問句 3-5 題

| | |
|---|---|
| **現象** | `templates/resource-list.md` 一邊訂資源清單的適用邊界是 4 到 8 個資源，一邊訂「這篇能回答你」寫三到五題。資源達到 6 個以上時，若要讓每個資源都有問句入口，題數必然超過 5 |
| **證據** | 這篇文章的資源清單有 6 項，Claire 人工微調時把問句從 5 題擴到 7 題，正是為了讓台南市議會觀測站、台南議會觀測機器人這兩個原本沒有問句入口的資源被涵蓋。查核總表第八節已記下這個發現，標為「未處理」 |
| **為什麼漏得過去** | 兩條規則是不同時間點分別加進模板的，加規則時沒有交叉檢查跟既有規則的數值範圍會不會在邊界情況打架 |
| **嚴重度** | **低到中**。不影響正確性，但每次資源數落在 6-8 之間都會重新撞到同一個矛盾 |
| **提案** | 「三到五題」改為「題數下限 3、且每個資源至少被一題指到」，不設硬性上限；防塞詞紅線保留（不為湊題數硬掰）。只改類型 B，類型 A 的「這篇能回答你」指向章節而非資源清單項目，不受同樣的矛盾影響 |
| **狀態** | ⏳ 待處理，另開 PR C |

## 發現 5：§2-1 沒指定要在哪個檢索面實測（僅記錄，這次不立規）

| | |
|---|---|
| **現象** | `SKILL.md` §2-1 只寫「逐詞實搜」，沒指定搜尋引擎或檢索面。這次執行時，派出的 `researcher` 子代理只跑了 Google（WebSearch 底層），沒測 Bing、沒測 AI 助理（ChatGPT／Perplexity）的即時檢索結果 |
| **證據** | 子代理自己在回報結果的「限制」段落誠實標註了這個缺口：「未測 Bing、未測 AI 助理的即時檢索結果，這是本次實測的主要缺口」 |
| **為什麼判斷先不立規** | 依 `立規則的流程` 反面清單第二條：只發生過一次、且問題本質（「該測哪個檢索面才能代表『使用者問 AI 時會不會被引用』」）需要先想清楚，不是隨手補一個檢索面就解決。貿然立規可能訂出一個沒想透的方法論 |
| **嚴重度** | 低（目前）。§2-1 本來就聲明它測的是「詞能不能進候選集合」，不是完整排名策略，這條缺口在既有免責聲明的範圍內 |
| **提案** | 不立規，記錄在案。若後續文章重複遇到「只測 Google 不夠代表」的具體案例，再回頭立規 |
| **狀態** | ⏸️ 建議先觀察 |

## 發現 6：疊床架屋的實測量測（回應「skill 是否高效」的提問）

| | |
|---|---|
| **現象** | 主線每次寫文章固定載入 `SKILL.md`＋當篇的 `template`，這兩份的內容有相當比例是規則的「理由與沿革」而非規則本身，且部分規則在多個檔案間逐字重複 |
| **證據（量測，2026-08-09）** | `SKILL.md` 34,739 字元，含 52 條規範性語句（強制／必須／不得／一律／絕不／不可）。`frontmatter` 一詞出現在 7 個檔案（`SKILL.md` 19 次）。`100 字截斷`、`CC BY 4.0`、`查核總表` 等規則同樣分散在 5-7 個檔案。實測代價：`PR #8`（frontmatter 一律不貼）一條規則改動就動了 5 個檔案。SKILL.md 內部最大的幾節（§6-3 授權 3,368 字元、§4-1-1 依據等級區位解釋 2,228 字元、§6-4 frontmatter 2,681 字元）多數內容是論證與沿革，不是可執行步驟 |
| **判讀** | 兩種重複要分開看：`checklists/` 的重複是必要的（給獨立驗收子代理用，且該子代理刻意要求自給自足、不給脈絡，重複是防呆）；`docs/` 幾乎不載入主線，躺著不花錢。**真正的浪費在 `SKILL.md` 內部，以及規則本身在 SKILL.md 與 template 之間的重複**——後者同樣不該動，因為那是防止寫作 AI「自評卻沒真的做到」的防呆機制（`checklists/README.md` 記錄的真實案例：第一篇交付文章自評全過，獨立驗收找出 7 條不通過） |
| **提案** | 把「為什麼有這條規則」的論證與沿革搬到新檔 `docs/SKILL規則的理由與沿革.md`，SKILL.md 只留規則本身、一句話理由、指向 docs 的指標。**規則語句、可執行步驟、格式範本、判斷對照表一律不搬**。字元數目標 SKILL.md ≤ 24,000（現 34,739），但明訂**達不到目標不算失敗，砍掉規則才算失敗** |
| **狀態** | ⏳ 待處理，另開 PR 0.5 |
