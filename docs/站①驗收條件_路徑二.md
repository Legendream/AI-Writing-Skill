## 現在哪裡壞了

**一、同一份文件裡兩句話打架**

| 位置 | 現在寫什麼 |
|---|---|
| `README.md:85` | Claude Code 要把 `civic-tech-writing-pipeline/` **複製到 `~/.claude/skills/`**，之後才會自動觸發 |
| `README.md:91` | clone 整個 repo **就是完整安裝，不必貼任何東西** |

相隔 6 行。

**兩句都只對一半。** 依 Claude 開發者文件（2026-09-02 查證），Claude Code 的
skill 是看檔案系統的，要放在 `~/.claude/skills/`（個人）或 `.claude/skills/`（專案）
才會自動觸發。所以正確的說法是分兩層：

- clone 下來、把資料夾指給 AI 看 → **可以用，但不會自動觸發**
- clone 下來、放進 skills 資料夾 → **會自動觸發**

**二、網站比 README 少一步**

`index.html` 的路徑二卡片只有 `git clone` 和「入口在根目錄的 `SKILL.md`」，
**完全沒有 skills 資料夾那一步**。只看網站裝 Claude Code 的人會漏掉，
然後在「怎麼確認裝對了」發現沒有「下一站：」，卻查不到原因——
因為疑難排解表的兩條解法都指向路徑一的 zip。

**三、Antigravity 有標題沒步驟**

它出現在路徑二的標題、也出現在「開始前你要準備什麼」的實測表裡，
但 clone 完之後該做什麼，兩份文件從頭到尾沒寫。

**四、門檻寫錯了對象**

路徑二現在的第一個畫面是一行 `git clone` 指令。Claire 2026-09-01 的觀察：
對不會用終端機的人，這行就是一道牆，而**這條路徑本來就可以不用碰終端機**——
直接叫 AI 去做就好。

**2026-08-18 那次 Antigravity 是怎麼裝的？**

> 我就是跟 Antigravity 說，請你抓這個 repo 的 skill（貼上連結）

**一句話，加一個連結。** 那次跑完了整篇文章與五份交付物
（見 `docs/可攜性測試診斷_2026-08-18.md`）。

這件事改變了兩個判斷：

1. **「叫 AI 去抓」不是我們想出來的簡化方案，是唯一有實測紀錄的 Antigravity 裝法。**
   原本的 `git clone` 寫法反而是後來補上、沒人真的照著走過的那個
2. 因此路徑二的主要說法應該是那句話，`git clone` 降為「會用終端機的人」的備選

**兩個工具的差別要寫清楚**（這是文件目前完全沒講的）：

| | 裝法 | 狀態 |
|---|---|---|
| **Antigravity** | 跟它說「請你抓這個 repo 的 skill」＋連結 | ✅ 2026-08-18 實測，跑完整篇 |
| **Claude Code** | 同一句話可以用，但要確保資料夾最後落在 `~/.claude/skills/`，之後才會自動觸發 | 依官方文件（2026-09-02 查證）；這個講法本身未實測 |

## 執行結果

17 條驗收條件全數通過。過程中方向被 Claire 修正過一次，範圍也追加了一項。

### 方向修正：主線改成「抓到工作資料夾」，不是「裝成 skill」

原本的規劃把重點放在「正確安裝成 skill」（skills 資料夾、重啟、`/skills` 驗收）。
Claire 2026-09-02 指出這是錯的方向：

> 我就覺得叫 AI clone repo 很簡單啊，需要執著於是不是安裝 skill 嗎？

判斷依據：對一年寫兩三篇的人，抓到工作資料夾就夠用，而且**那才是唯一有實測紀錄的做法**
（Antigravity，2026-08-18）。「裝進 skills 資料夾」是給常寫的人的優化，不該當主線。

因此 `git clone`、`mkdir`、`cp`、重開 Claude Code、`/skills`、斜線指令**全部刪除**，
路徑二從九段縮成四段。

### 順帶修正的事實錯誤

`README.md` 原本寫「其他工具沒有 Claude 的技能自動觸發機制」。查證後這句是錯的：
Antigravity 也支援 SKILL.md 與自動觸發，全域路徑是 `~/.gemini/config/skills/`
（依 [Antigravity 官方文件](https://antigravity.google/docs/skills)，2026-09-02 查證）。
問題出在**做法**（抓到一般資料夾不會自動觸發），不在工具。

### 追加範圍

- **可讀性整理**（Claire 指定）：正向表述為主、減少技術名詞、讀起來要順
- **FAQ 那句已經不成立的話**（Claire 拍板併入）：
  `docs/FAQ草案` 原寫「抓到本機也一樣會自動生效」，那是今天下午釐清之前寫的

### 站④：獨立驗收（acceptance-reviewer）

**修掉的（4 項，全是本 PR 造成的）**

| 問題 | 修法 |
|---|---|
| **教使用者講的路徑少一層。** 抓下來會多一層以 repo 命名的資料夾，而 `README.md:120` 自己就記著這個坑（「口述路徑很容易漏掉中間那層資料夾⋯⋯接手的 AI 在根目錄找不到而卡住」） | 改成「照**你剛抓下來那包裡的** `civic-tech-writing-pipeline/SKILL.md` 進行」，並說明這幾個字的作用 |
