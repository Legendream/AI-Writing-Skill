## 一、§1-5 AI 主動搜尋候選素材時，怎麼呈現給人拍板

| | |
|---|---|
| **現象** | 這是 skill 第一次被要求「素材盤點階段就主動混合兩種來源」（甲方骨架頁 7 個連結＋AI 自行補入 5 項）。§1-4 只講「AI 自行補入的素材必須標明」，觸發情境是「素材不足時的補救」，沒有涵蓋「一開始就要 AI 主動找」這種用法，也沒說候選要怎麼呈現給人挑 |
| **實戰做法** | AI 先列候選＋每個附一句話「為什麼夠格」→ 一次問完所有待拍板事項 → 拍板後才進入讀後憑證 |
| **為什麼要先拍板再深讀** | 讀後憑證是重工序（讀說明頁、找逐字引述、挖意外細節）。先深讀再給人挑，被剔除的工就白做；更糟的是沉沒成本會讓 AI 傾向替已經讀完的素材說話 |
| **實作位置** | `SKILL.md` §1-5（新增小節） |
| **狀態** | ✅ 已實作 |

**一個實作時特別寫進去的教訓**：候選階段的「夠格判準」只能靠快速查核，深層問題仍會在
讀後憑證階段才浮現。本篇的「青年好政 Let's Talk」就是拍板通過後，才在讀說明頁時發現
站台三週後要關閉，只好回頭再問一次。規則因此明訂：**這種情況要再回去問，不要自行改掉
使用者拍板過的決定**。

**下一篇（第四篇）要驗證的**：這條規則是依單一案例寫的，Claire 已同意下一篇再測一次。
測試重點是「候選數量比上限多列一兩個」與「一次問完」這兩點在素材更多時還撐不撐得住。

## 二、§2-1 步驟 3：主標題要獨立實測，不是核心主題的附屬品

| | |
|---|---|
| **現象** | §2-1 步驟 3 的回填清單寫「核心主題那一行、各節標題、主題標籤」，沒有把主標題列成獨立項目。本篇因此只測了核心主題的詞，主標題直接沿用同一批詞草擬成「意見要投到哪裡？」 |
| **怎麼被抓到的** | 不是 AI 自己發現的，是 Claire 看到草稿後退回：這批工具做的是「整理多方利害關係人的討論」，不是「投遞意見」，而且 Polis 的核心動作剛好也叫投票（對主張投同意／不同意），混用會誤導 |
| **回頭補測才發現的第二個問題** | 「意見整理」這個原本打算用在標題的詞，前 10 條結果全是日文（意見集約ツール、思考ツール），與「意見綜整 工具」完全相同的下場。若沒有補測，這個詞會直接進標題 |
| **實作位置** | `SKILL.md` §2-1 步驟 3（改寫為四個獨立位置＋合併檢查）、檔案格式範本（回填結果增列「主標題」與「合併檢查」）、`checklists/` 兩份各增一條 |
| **狀態** | ✅ 已實作 |

**額外寫進規則的一點**：主標題與核心主題若各自扛不同的詞，要檢查**合起來**有沒有漏掉
必要的限定詞。本篇定稿的主標題「一群人的意見怎麼收斂成共識？公民參與管道與討論工具整理」
不含「公共政策」，而實測顯示「意見」「共識」缺了公共政策限定會整批落到企業管理領域
（「怎麼蒐集大家的意見 找出共識 工具」前 10 條全是 SWOT、便利貼、SurveyMonkey），
因此該限定詞改由核心主題那句話扛。

## 三、§2-1-1 檢索面規則（連續兩次撞到，達立規門檻）

| | |
|---|---|
| **現象** | §2-1 只規定「逐詞實搜」，沒指定在哪搜。連續兩篇（`短文_法律立法歷程與議會監督`、本篇）都只測了 Google，且都沒在交付物裡交代這件事 |
| **為什麼這次才立規** | 依 idea repo `docs/立規則的流程.md` 要求先診斷再立規。上一輪只有單一證據，診斷文件標為「僅記錄，不立規」；本次是第二次撞到同一限制，達門檻 |
| **實作位置** | `SKILL.md` §2-1-1（新增小節）、步驟 2 加指向、檔案格式範本增列「實測檢索面」必填欄位、`checklists/` 兩份各增一條 |
| **狀態** | ✅ 已實作 |

### 為什麼第二個檢索面預設是 Bing（查證後的理由，不是直覺）

初次提案時「Google＋Bing」是憑印象寫的，沒有根據。Claire 追問後查證，發現**結論對但
理由錯**，規則因此改寫成有依據的版本：

- **台灣搜尋引擎市占**（StatCounter，2026-02）：Google 82.69%、**Yahoo 奇摩 10.77%**、
  Bing 5.86%。**Bing 不是第二名**，Yahoo 奇摩才是
- **但 Yahoo 奇摩的自然搜尋結果由 Bing 提供**（微軟與 Yahoo 技術整合，台灣約 2011 年完成），
  所以測 Bing 等於一併涵蓋 Yahoo 奇摩，合計約 16.6%
- **AI 助理的檢索來源分歧，沒有單一索引能涵蓋全部**：Copilot 建在 Bing 索引上、
  Gemini 用 Google、Claude 用 Brave 獨立索引、ChatGPT 已改用自家索引（OAI-SearchBot）、
  Perplexity 用自家索引

規則因此定為「Google 必測、第二個預設 Bing、有理由可改測別的、但一律要寫明測了哪些」，
而不是死板規定組合。**目標不是「測全」（做不到），是「不要只測一個卻沒人知道」。**

## 四、§4-1 取證方式分級：一手直讀 vs 工具二手摘要

| | |
|---|---|
| **現象** | 依據等級表只分「一手逐字可查／推斷／AI 推測／查無來源」，沒有區分「AI 親眼讀到原文」與「`WebFetch`／`WebSearch` 由另一個模型讀完後回傳轉述」 |
| **為什麼這是實質差異** | 不是「看得清楚 vs 看得模糊」，是**看過 vs 沒看過**。轉述的模型可能漏講、改寫、把不同段落併成一句，而 AI 沒有原文可對照，無法察覺。**工具回傳的「逐字引述」同樣不可信**——那個字串也是轉述模型產生的，可能是重建而非複製 |
| **實作位置** | `SKILL.md` §4-1（新增「取證方式也要分級」小節，上限 ★★★★☆）、`checklists/` 兩份的依據等級條目各增一段 |
| **狀態** | ✅ 已實作 |

### 三筆實證（同一天補做一手直讀撈出來的）

本篇原有三項具體數字停在二手摘要等級。改用瀏覽器直接讀原文重核後，**三次直讀全都撈出
摘要漏掉的實質內容**：

1. **JOIN 的回應期限**：我的 `WebFetch` 與獨立驗收員的 `WebFetch` **兩次都只回報
   「2 個月內回應」**。直讀「公共政策網路參與實施要點」第八點(五)，原文緊接著還有
   「但權責機關未能於期間內完成回應者，得延長之，其延長期間不得超過二個月」。
   **讀者實際可能等 4 個月，不是 2 個月。**
   ⚠️ 這一筆同時證明了**兩次獨立工具查證得到一致答案，也不能取代自己讀一次原文**
2. **Polis 規模紀錄**：摘要只給「33,000 人」，原文還有「1,000 則留言、近 200 萬張票」
3. **Polis 適用下限**：摘要完全沒提。官方 FAQ「What is Polis not?」明載
   「A tool for gathering data from groups of less than 50 to 100 people」——
   **漏掉這條會害讀者白做工**（辦 20 人工作坊的人用 Polis 必失敗）。
   依 §6-0 屬於「讀者要用這個工具就必須知道的事」，已補進正文使用提醒

第 1、3 筆都不是「數字標錯」，是**整段關鍵限制條件從摘要裡蒸發**，這是二手摘要最危險的
失效模式：它給你的東西看起來完整，你不會知道少了什麼。

## 五、checklists K／L 節：發布後驗證條目的階段順序 bug

| | |
|---|---|
| **現象** | 驗收條件要求 `_驗收紀錄/` 有「發布後驗證檔案」，否則相關三條一律判不通過。但 `SKILL.md` 的階段順序是 §6-1 獨立驗收 → §6-2 決定發布位置 → 實際發布，**第一輪獨立驗收進行時文章還沒發布，那份檔案在邏輯上不可能存在** |
| **實際造成的傷害** | 本篇第一輪獨立驗收因此產生三個「不通過」，且依報告慣例排在最前面。那不是文章的問題，是驗收條件與 `SKILL.md` 對不上，這類假陽性會掩蓋真正的問題 |
| **怎麼被發現的** | 由獨立驗收本身冒出來——驗收員照條文忠實判了不通過，主線比對 `SKILL.md` 階段順序後才認出是條件本身的 bug |
| **實作位置** | `checklists/驗收條件_領域資源短文.md` K 節（51-53 條）、`checklists/驗收條件_方法論長文.md` L 節（49-51 條），兩份各加一段前置說明 |
| **狀態** | ✅ 已實作 |

修法方式：這三條只在「已完成發布」的驗收輪次適用；發布前驗收一律標
「**不適用，待發布後補測**」，不是「不通過」。

## 實作時當場攔下的一個事故

改 `checklists/驗收條件_領域資源短文.md` 時，在 L 節尾端新增 56、57 兩條，
**與既有 M 節的 56、57 撞號**。這正是
`g0v-Articles-repo` 交接筆記警告過的那個事故型態（多個改動各自在清單尾端加條目，
合併後條號重複）。

當場改法：M 節順延為 58、59。並在完成後用指令驗證兩份清單的條號連續性：

```
條目總數 59、最大號 59、重複 0、缺漏 0（領域資源短文）
條目總數 57、最大號 57、重複 0、缺漏 0（方法論長文）
```

**教訓**：在編號清單尾端加條目前，先看該檔案後面還有沒有別的節。
交接筆記記的是「多個 PR 平行改同一份清單」會撞號，這次證明**單一 PR 內連續改兩處也會撞**。
