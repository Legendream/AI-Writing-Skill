# docs／規則的依據

**這裡不是使用說明，是「為什麼」。** 想直接用 skill 寫文章的人不必讀這裡，
看 [`../civic-tech-writing-pipeline/SKILL.md`](../civic-tech-writing-pipeline/SKILL.md) 就好。

會需要讀這裡的情況有三種：

- 你想知道**某條規則為什麼存在**，才好判斷在你的情境該不該調整
- 你想知道**哪些規則其實沒有證據**，不想把猜測當定論用
- 你要向別人（委託方、社群、審查者）交代這套方法憑什麼這樣設計

## 這些文件怎麼長出來的

規則不是設計出來的，是撞出來的。流程是：

```
實際寫一篇 → 出錯或被挑錯 → 問「為什麼這類錯漏得過去」
           → 寫成規則提案（放這裡）→ 改 SKILL.md → 下一篇驗證
```

所以這裡的文件會持續增加。**每次獨立驗收之後，把「skill 沒防住的類型」抽出來寫一份**，
不要只修那一篇文章就算了——那樣同一種錯下次還會再犯。

判斷標準很簡單：**只有那一篇會犯的錯，修完就結束；換一篇還會再犯的，寫進這裡。**
