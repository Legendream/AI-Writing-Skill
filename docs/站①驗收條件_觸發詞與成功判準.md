## 這個 PR 要解決什麼

同一個 bug 的兩面：

1. **叫不出來**——使用者用自然的說法描述需求時，skill 不會觸發
2. **叫不出來你還不知道**——網站教的成功判準會給出假陽性

## 證據（2026-09-02 實測，claude.ai，Opus 4.8）

四次測試，除了句子以外條件相同（`writing` skill 已關閉、code execution 已開）：

| 句子 | 觸發？ | 證據 |
|---|---|---|
| 我想寫一篇介紹某個公民科技工具的文章 | ❌ | 無 skill 讀取紀錄，無固定結尾 |
| 我想寫一篇介紹某個公民科技工具的文章（`writing` 未關閉時） | ❌ | 讀到的是 `writing/SKILL.md` |
| 我想寫一篇公民科技的**方法論文章** | ✅ | `ls -R /mnt/skills/plugins/civic-tech-writing-pipeline/`；結尾「下一站：素材盤點」 |
| 我想整理某個領域的公民科技**資源清單** | ✅ | 認出類型 B；引用 §4-1、§1-2、§2-1-1；結尾「下一站：素材盤點」 |

**診斷**：現行 `description` 的觸發詞全是**產物類型**（方法論文章／資源清單／公民科技指引），
而選文體是這個 skill 的第一份工作（`SKILL.md:37`）。等於要求使用者先講出只有走完站①才會知道的詞。

**通則（可寫進 docs 的規則提案）**：
> 觸發詞要用「主題」，不要用「產物類型」。使用者第一句話就知道自己的主題，
> 但不知道該用哪種文體——文體是走完站①才產出的判斷。

**第二個 bug**：`index.html` 現行判準是「先問問題，就代表裝成功了」。
但四次測試中未觸發的兩次，Claude **都問了問題**，而且問得很好。這個判準會產生假陽性，
使用者會以為裝成功、一路寫下去。

## description 改寫草案

只加不減——原有的三個內部術語觸發詞全部保留，另外補上主題詞與新手講法。

```yaml
description: >
  人機協同寫作技能，用於產製公民科技知識庫文章。當使用者想寫**公民科技、開放資料、
  g0v、數位治理、參與式民主**相關的文章時使用——包括介紹某個工具或專案、整理某個
  領域有哪些資源、記錄自己的實作方法，或說「寫一篇公民科技的文章」、「整理資源清單」、
  「寫方法論文章」、「公民科技指引」、「為公民科技知識庫貢獻內容」。
  本技能支援兩種文體：方法論長文（介紹專案研究與實作方法）與領域資源指南（整理某領域
  既有專案的資源與機制設計，供提案者借鑑）；**文體由本技能在開始時與使用者確認，
  不預設使用者事先知道要寫哪一種**。涵蓋素材盤點、大綱、初稿、事實查核、風格套用
  到交付的完整流程，內建強制事實查核關卡與 AI 可讀性格式規範。
```

（實際寫入時不含 `**` 粗體記號，此處只為標示改動處。）

**設計理由**

- **領域詞當護欄**：公民科技／開放資料／g0v／數位治理／參與式民主。夠廣到新手講得出來，
  夠窄到不會跟泛用寫作 skill 搶（那個 skill 的觸發詞是「幫我寫一篇」「部落格」「電子報」）
- **最後那句「不預設使用者事先知道」有雙重作用**：告訴 Claude 該先問，
  也告訴它「使用者沒講文體是正常的，不要因此不觸發」

## 驗證順序（有雞生蛋問題，必須照這個順序）

`.github/workflows/package-skill.yml` 只在 **push 到 main** 且路徑符合
`civic-tech-writing-pipeline/**` 時重新打包。所以 PR 還沒合併時，
claude.ai 的下載連結拿到的仍是舊 zip——**不能靠它驗 B1–B5**。

正確順序：

1. Claude 改 `SKILL.md` 的 `description`，自驗 F1–F6
2. Claude 用與 workflow 相同的邏輯（Python `zipfile`，UTF-8 檔名旗標）
   在本機打出一份 zip，交給 Claire
3. **Claire 在 claude.ai 刪掉現有的 skill，改上傳這份本機 zip**，跑 B1–B5
4. B1–B5 全過 → Claude 改 `index.html` 與 `README.md`，自驗 W1–W9 與 P1–P8
5. 跑 `/code-review` + 派 `acceptance-reviewer`
6. 開 PR，說明貼上本清單與逐條結果
7. 合併後 workflow 自動重打包，Claire 再把 claude.ai 上的 skill 換回正式版

⚠️ 第 3 步要 Claire 先刪掉舊的再上傳，否則會有兩個同名 skill 互搶，
