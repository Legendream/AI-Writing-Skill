# 站①驗收條件：風格檔去個人化（`styles/default.md`）

**狀態：驗收條件已定案（2026-09-05），16 條，實作中。**

---

## 這批要解決什麼

`styles/claire.md` 會被自動套用而沒有先問。兩次實測：

| 日期 | 條件 | 結果 |
|---|---|---|
| 2026-09-02 | claude.ai 五次觸發 | 一次自動套用 |
| 2026-09-04 | 瘦身 PR 四次觸發實測 | E1、E3 自動套，E2、E4 有問 |

出處：`docs/待辦總覽.md` 三、`docs/站①驗收條件_SKILL瘦身.md` 的「E. 實測」一節。
（兩份文件對「第幾批證據」的計數不一致，一份寫第二批、一份寫第三批。以上表的
日期與次數為準。）

同一包 skill、相隔幾分鐘、不同結果，是執行抖動。但根因不是規則寫得不清楚：
**交付包裡唯一一份填好的風格檔就是作者本人的聲音**，AI 抖動時只有那一份可以抓。
公版不該預設套用任何一位作者的聲音。

## 做法（2026-09-05 討論後定案，與原「做法 A」的差異已標明）

1. 新增 `styles/default.md`，是一份**寫作大原則**，不是一份填好的風格檔
2. **`claire.md` 移出交付包**到本機。⚠️ 這一項偏離原本拍板的做法 A（原話是
   「`claire.md` 留作填寫實例」）。改變理由：包裡只要留著任何一份填好的個人風格檔，
   防線就只剩「AI 有沒有讀進檔頭那行標記」，而證據顯示它會抖；一份都不留，
   誤套在結構上不可能發生
3. 沒有風格檔時**不再多問一句**，直接套 `default.md` 並在回覆裡說一聲
4. 範文維持現狀，仍請使用者提供，且在 `styles/README.md` 擺成主要路徑、
   風格檔擺成選配補充

## 明確不做

- **不做「上傳範文自動萃取成風格檔」**。2026-09-05 Claire 判斷：表格式風格檔本身
  就寫得機械，使用者看了難有感覺，補這一步價值不足
- **不做 `style-template.md` 整份翻修**，只換掉會被當公式套的示範（理由同上）
- `checklists/` 兩份條文（已查證：兩份都沒有驗風格檔的條文，`grep 風格` 只命中一行
  沿革註腳）
- `.github/ISSUE_TEMPLATE/`、`README.md` 的 58 處多餘空格、`og:image`
