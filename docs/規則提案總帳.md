# 規則提案總帳

**這份文件解決的問題**：每篇文章交付時都會產出一份「本篇產生的 skill 規則提案清單」，
存在 `g0v-Articles-repo` 的 `_驗收紀錄/`（或本 repo 的 `試跑紀錄/`）裡。目前有 8 份，
分散在兩個 repo，狀態欄各自寫著「未搬運」「已併入」。**沒有一個地方能一次看出
「哪些提案累積到第二次了、該立規了」**——你自訂的門檻是「一次記錄、兩次立規」
（見 `docs/立規則的流程.md`），但門檻要被觸發，得先有人同時打開八份清單去數。

這份文件就是那個集中檢視點。**不重寫來源清單的判斷**，只彙整、標記狀態，
細節與完整論證留在各自的來源檔案。

最後更新：2026-09-01（字數下限退役；標題層級改為相對、兩個區塊改為選配；章內順序改由子標題承載，並修正第一批立規緣由裡一句未查證的宣稱）。

## 怎麼維護這份文件

1. 每篇文章交付、產生新的「本篇產生的 skill 規則提案清單」時，回來這裡新增一列
2. 新提案若跟既有某列談的是同一件事，**合併成同一列、累計次數 +1**，不要重複列兩行——
   這是這份文件存在的唯一理由：讓「達到兩次」這件事看得見
3. 提案被搬進 `SKILL.md`／`checklists/` 後，把該列移到「已併入」，附上 PR 連結
4. 這份文件不重新論證每個提案該不該立規——那是來源清單與 `docs/立規則的流程.md` 的事，
   這裡只負責讓狀態一眼可見
