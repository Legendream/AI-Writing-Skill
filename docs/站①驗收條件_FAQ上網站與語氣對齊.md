# 站① 驗收條件：FAQ 上網站 ＋「開始前你要準備什麼」語氣對齊

定於 2026-09-03，經 Claire 確認後進入實作。對應待辦總覽第一項與三B 最後一項。

## PR 目的

讓還沒安裝的讀者，在網站上讀到一致的跨工具說法。

FAQ 草案（`docs/FAQ草案_跨工具與使用經驗.md`）已在 2026-09-02 改到定稿品質，
但一直沒上網站；同時 `index.html` 與 `README.md` 的「開始前你要準備什麼」
工具表仍寫著 FAQ 已經拿掉的內部細節（驗收條數），而那張表面對的也是
還沒安裝的讀者。兩件事講的是同一批讀者的同一個問題，一次對齊。

## 開始前拍板的四件事（Claire 2026-09-03）

1. **FAQ 位置**：放「裝完之後，怎麼確認裝對了」之後
2. **Q1 結尾的留言邀請**：保留原句。已知留言區尚未上線（待辦第六項），
   接受這段空窗期
3. **README 不放 FAQ**：只做工具表與路徑二的語氣對齊，避免同一件事在兩處各自演化
4. **ChatGPT／Gemini 那格的未查證斷言一起改**：留著會跟新 FAQ 當場矛盾，
   而消滅這種不一致正是本 PR 的目的

## 驗收條件

### A・FAQ 上網站（只上 `index.html`）

- A1 新增「常見問題」`<h2>` 區塊，位置在「裝完之後，怎麼確認裝對了」之後、
  「這套流程寫出來的文章」之前
- A2 三題順序照草案：能不能用 → 會不會一樣 → 用起來像什麼
- A3 每題第一行是粗體結論，且結論告訴人可以怎麼做
- A4 Q1、Q2 的表格沿用現有 `table` 樣式，外面包 `overflow-x:auto`
- A5 FAQ 段落內沒有破折號
- A6 FAQ 段落內不出現內部細節：驗收條數、規則編號、`docs/` 檔名、站別代稱
- A7 Q1 結尾保留「歡迎留言告訴我們結果」。驗收時「網站上找不到留言框」
  不算缺陷，那是已知且已拍板接受的空窗期
- A8 新增的外部連結都帶 `target="_blank" rel="noopener"`
- A9 只用既有 CSS 變數，不寫死顏色，深淺色模式都可讀

### B・工具表語氣對齊（拿掉數字、留下結論）

- B1 兩檔工具表的 Claude Code／Antigravity 那列刪掉驗收條數，改成不帶數字的結論
- B2 同表 ChatGPT／Gemini 那格的「沒有會自動觸發的 skill 安裝機制」這句
  未查證的機制斷言，改成與 FAQ Q1 一致的正面表述（規則怎麼進去：每次對話自己帶進去）
- B3 `index.html` 與 `README.md` 兩處語意一致
- B4 兩檔都找不到殘留的驗收條數

### C・路徑二補上結論

- C1 兩檔路徑二段落，「2026-08-18 交給 Antigravity、跑完一整篇」之後
  補上獨立驗收不能省的結論，不帶數字
- C2 與 B1 用同一個講法

### D・不製造新矛盾

- D1 FAQ、工具表、路徑二三處對「Antigravity 好在哪、哪裡要補人工」說法一致
- D2 FAQ Q3 提到的「Claude Code 附了現成的檢查助手」，本 PR 不補安裝說明
  （那是待辦三C），但措辭不能暗示有現成步驟可照做

### E・收尾

- E1 `docs/FAQ草案_跨工具與使用經驗.md` 標為已上網站、正本在 `index.html`
- E2 `docs/待辦總覽.md` 刪掉第一項與三B 最後一項；第六項的留言區那條補一行
  「上線後要回頭把 FAQ Q1 的留言邀請兌現」
- E3 站④跑 `/code-review` ＋ 派 `acceptance-reviewer`。本 PR 是在拿掉數字、
  沒有新的可回溯數字，不派 `number-auditor`

## 驗證方式
