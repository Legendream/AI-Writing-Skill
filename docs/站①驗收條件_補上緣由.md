# 站①驗收條件：補上做這套 pipeline 的緣由

**狀態：已執行完畢，12 條全數通過。** 2026-09-02 建立並完成。

---

## 問題

`index.html` 開頭講的是**怎麼做**（哪幾段交給 AI、哪幾段人自己判斷）與
**能幫你省什麼力氣**。整頁沒有一句話說**這東西為什麼存在**，
讀者會把它讀成一個寫作效率工具。

副作用是：規則沒有目的撐著，讀起來就是刁難。最明顯的例子是
「文章授權建議 CC BY 4.0 或更寬鬆」——Claire 2026-09-02 說明那不是硬規定而是鼓勵，
理由是資源要能擴散。網站上目前沒有這句話。

## 依據（2026-09-02 直接讀報告原文，非摘要）

來源：`https://report.claire-cheng.com/`
《臺灣公民科技生態系與需求調查報告》，g0v.tw 揪松團問卷研究，作者鄭婷宇（Claire），
127 份有效樣本，資料截至 2026/07/20。

三段可以支撐緣由的原文：

1. **研究建議的第一個標題**
   > 一、兩件事最值得先做：讓人找得到專案、把「成果如何落地」寫清楚

2. **擋住新人的不是能力**（第七章標題與內文）
   > 還沒參加公民科技專案的人，過半數是因為不知道有哪些專案或議題可以加入
   >
   > 這三項原因都跟缺乏資訊與入口相關，並非能力的問題。
   > 「覺得要會寫程式，技術門檻太高」只是排名第四使人卻步的原因

3. **該寫的人正卡住**（第三章標題）
   > 讓貢獻者感到心累的，是專案進度停滯不前、核心成員累垮

**要誠實面對的一點**：報告也說五個候選方法論主題「全部落在魅力型」——
有了會加分，但還不到不寫會被抱怨的程度。**所以文案不能把這套東西講成社群的剛需。**

## Claire 指定的分寸（2026-09-02）

> 不用砸一堆數字讓讀者被嚇到，適度提到，讓讀者知道我們有問題意識，這樣就夠。

## 驗收條件

### 一、內容

- [x] 緣由寫在**開頭 lede 附近**，不另開「我們的初衷」之類的獨立章節
2. **不出現任何問卷數字**（百分比、樣本數、排名都不寫）
3. 有一個連往 `https://report.claire-cheng.com/` 的連結，並說明那是什麼
4. 講出這套東西的定位：**不是幫你寫文章，是把已經存在但沒被寫下來的經驗
   變成別人能照著走的資源**
5. **不把這套東西講成社群的剛需**——報告自己說那些主題是「魅力型」，
   文案不得超出這個把握程度

### 二、寫法（沿用 FAQ 那三輪定下來的原則）

6. 正向表述為主
7. 不堆疊技術名詞
8. 全文無破折號
9. 篇幅**兩段以內**，讀完不超過 30 秒

### 三、沒有弄壞別的

10. `index.html` 標籤仍完全對稱
11. 改動只在指定段落，八站表、路徑一二、準備表、判準一字未動
12. 未新增或修改任何樣式規則

## 執行結果

### 定案的文案

```
為什麼要做這個

這是 g0v 揪松團委託的專案，分成兩半。前半是一份問卷研究，去看台灣公民科技社群
卡在哪裡。其中一項發現是：擋住新人的多半不是技術門檻，而是不知道有哪些專案可以
參與、找不到入口。研究給的第一個建議，就是「讓人找得到專案、把成果如何落地寫清楚」。

後半就是這套流程，它回答的是「那誰來寫」。做過專案的人心裡都有東西：怎麼開場、
哪裡踩過雷、什麼做法真的有效。這些整理成文章，能替剛起步的提案者指路，
也能讓做到一半卡住的人看見別人怎麼處理過同樣的問題。

只是動筆很花力氣，也常常不確定自己寫的，對背景不同的人讀不讀得懂，於是多半留在
各自的腦袋裡。這套流程把「把經驗寫成別人能照著走的資源」拆成一站一站的步驟，
讓這件事可以不只靠少數幾個人。
```

三段各約 100 字，零個問卷數字，一個連往報告的連結。

**素材來源**：第二、三段的內容出自 Claire 2026-09-02 的原話——

> 我希望這個解方不只是靠我、靠某幾個人去寫，是降低門檻更多人都可以輸入自己的知識與
> 經驗⋯⋯有時候大家可能受限於懶得自己動筆，或是不確定自己的表達，是否對於背景相異的
> 人來說難以看懂，所以會造成成果沒有讓更多人接收到，這很可惜

「成果」一詞太空，Claire 指示要具體化，因此改寫成兩個對象：
**剛起步的提案者**（指路）與**做到一半卡住的人**（借鑑他人做法）。
這兩個對象正好對應兩種文體。

### 授權規則補上目的（`civic-tech-writing-pipeline/SKILL.md`）

`§6-3` 原本只有防守式論證（「加嚴擋不住 AI 卻擋得住人」）。補上目的：

> **為什麼要開這麼寬**：因為這套流程的目的就是**讓資源擴散**。寫這些文章是為了替
> 剛起步的提案者指路、讓卡住的人有前例可循；授權開得越寬，能接到手上的人越多。
> **這是鼓勵，不是限制作者。**

「開始前必問」第 4 題也帶一句理由——2026-09-02 實測時，Claude 問這題的講法是
「授權只能是 CC BY 4.0 或更寬鬆，不能加 SA / NC / ND」，聽起來像規定。

### 站④：獨立驗收（acceptance-reviewer）

只給 `index.html`（第一次來的人不會去看 repo），問四題，重點是第四題
「讀到第幾段才回答得出『為什麼會有這個東西』」。

**回答：「第二個小節的三段⋯⋯整體算快，位置對。」** 並評第 2、3 段
「因果連得順，一次就讀懂，沒有多餘句」。緣由的目的達成。

回報 12 項，**修掉 5 項**：

| 問題 | 修法 | 成因 |
|---|---|---|
| **把研究結論講太大**。寫「結果顯示，擋住新人的⋯」，但那是報告第七章的發現，第三章才是「核心成員累垮」 | 改成「**其中一項發現是**」 | 本 PR 新寫的 |
| 「這個專案分兩半」指涉不明，reviewer 讀兩次才懂「這個專案」不是指這套流程 | 改成「這是 **g0v 揪松團委託的專案**，分成兩半」 | 本 PR 新寫的 |
| 「免費版可以使用 claude.ai 內建的 skill」**沒有出處支持**（reviewer 實際讀了被引用的文件，只支持 Pro 以上那半句） | 拿掉沒依據的半句，兩檔都補上出處連結 | PR #70 留下 |
| 表格前導句寫「以下是我們自己實測到的狀況」，但第三列是「我們沒有實測過」 | 改成「哪些工具用得起來、哪些我們還沒測」 | PR #70 留下 |
| `title` 與 `og:title` 是「把寫作流程拆給 AI 做」，跟頁面主張相反，貼到 Slack 讀起來就是全交給 AI | 改用 h1 的雙邊說法「哪幾段交給 AI，哪幾段人自己判斷」 | 既有，但這個 PR 的目的就是第一印象 |

### 不併入本 PR 的既有問題

**⚠️ 需要 Claire 回答才能處理的一項**

- **「公民科技知識庫」是進門第一個詞，卻從頭到尾沒有解釋。**
  全頁「知識庫」只出現 4 次且全在頁首（title、meta、tag、lede），正文再也不出現。
  讀者不知道是誰的知識庫、文章寫完要投到哪。
  **未解的事實問題**：報告裡提到揪松團經營的是「台灣公民科技資料庫」，
  與網站寫的「公民科技知識庫」是否為同一個東西，無法從現有資料判斷，不得臆測。

**其餘七項**

1. 「省下大量排版」對不上八站裡的任何一站，也沒有對應產出
2. 「三個硬門檻」是哪三個，全頁未說明也無連結
3. 「方法論長文」先用後定義，中間隔了 237 行
4. 開頭「可以攤開給人看的稽核軌跡」無保留語氣，與後面 19/66 的實測數據語氣斷裂
5. 「只有第一份會公開發表」與範例區「全部公開在 repo 裡」讀起來像矛盾
6. `.placeholder` 是死 CSS（定義了零處使用）
7. HTML 註解含內部 TODO，且有一個簡體字「换」
