# 站① 驗收條件：純聊天介面改推 Gem／Custom GPT，拿掉「貼整份」

定於 2026-09-03，Claire 拍板後進入實作。

## 為什麼改

網站與 README 原本教純聊天介面的使用者「把 `SKILL.md` 貼進對話」。這條路徑有兩層問題：

1. **貼不進去。** `SKILL.md` 目前 33,042 字元（用 Python 量；`wc -m` 在未設 locale 時
   回的是位元組數 81,592，不要採信）。多數聊天介面貼不完整
2. **就算貼進去了，讀法也不對。** 這套流程自己的診斷是：純聊天介面「挑看起來相關的
   段落來讀」，會先撈到後面的寫作技巧、跳過開頭的素材盤點，直接動筆

所以改成指向 Gem／Custom GPT：把規則上傳成知識檔，建一次、之後開對話就有。

## 這個改動沒有解決什麼（重要，想改回來的人先讀這段）

**Gem／Custom GPT 解決的是「持久性」，不是「讀取順序」。** 知識檔的讀法一樣是
「需要時撈相關片段」，不是從頭讀完。所以第 2 層的風險原封不動。

這表示：

- 不能寫成「建了 Gem 就會照流程走」。**沒有任何證據支持這句**
- FAQ 第一題的結論不變：**這道關卡改由你來守，自己拿檢查清單對照成品**。
  那才是補償機制，Gem 不是
- 我們是拿一條沒實測的路換另一條沒實測的路。「我們沒有實測過」的標記一定要留著

若哪天 `SKILL.md` 瘦身到官方建議的量級（見待辦的 Skill 本體那節），貼整份會重新
變成可行做法，這個決定值得重新評估。

## 附帶解決的一件事

改成 Gem 之後，工具表欄名「怎麼裝」自己就通了：三列變成「上傳 zip 裝成 Skill／
clone 整個 repo／建成 Gem 或 Custom GPT」，全都是安裝動作。

2026-09-03 獨立驗收曾建議把欄名改成「規則怎麼進去」，理由是那格填了一個
「不用裝」的答案。該建議因本次改動而失效，不需要處理。

## 驗收條件

### A・拿掉貼整份

- A1 `index.html` 工具表 ChatGPT／Gemini 的「怎麼裝」格改成建 Gem／Custom GPT
- A2 `README.md` 的 ChatGPT、Gemini 兩條拿掉「貼進對話」，只留建 Gem／Custom GPT
- A3 `README.md` 的「規則得靠你每次對話自己帶進去」一併改
- A4 兩檔都找不到「每次對話自己帶進去」這類殘留
  （`README.md` 描述路徑二優點的「不需要把規則內容貼進對話」是正確用法，不算殘留）

### B・FAQ 第一題跟著對齊

- B1 Q1 表格第一列不再以「持久性」作對比（Gem 也是建一次就有，原本的對比會失效）
- B2 第二列「AI 怎麼讀」維持不動，那才是真正的差別
- B3 Q1 的結論與建議段不變

### C・誠實標記不准鬆動

- C1 工具表第三欄「❌ 我們沒有實測過」原樣保留
- C2 Q1 底部「這一題目前是推論，我們還沒實測」原樣保留
- C3 全篇不出現「Gem 效果比較好」之類未實測的比較級宣稱

### D・不擴大

- D1 不在網站新增 Gem／Custom GPT 的逐步操作教學
- D2 FAQ 段落沿用既有規則：無破折號、無內部細節

### E・收尾

- E1 本檔即為理由紀錄
- E2 站④：`/code-review` ＋ `acceptance-reviewer`
