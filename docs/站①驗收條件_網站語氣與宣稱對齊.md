# 站① 驗收條件：網站宣稱對齊實情，全站清除破折號

定於 2026-09-03，Claire 確認後進入實作。對應待辦第二項 B 批三條。

## 為什麼改

三處措辭與實情有落差，改的是措辭本身，不改變任何實際做法：

1. 頁尾「只保證在 Claude 環境下運作」用了「保證」這個全站唯一的法律味字眼，
   跟其他地方一律用「實測過／沒實測過」的體例不一致
2. 工具表把 Claude Code 與 Antigravity 併列一列，但實測欄寫的是 2026-08-18
   那次可攜性測試的成績。依 `docs/可攜性測試診斷_2026-08-18.md` 測試設定表，
   執行平台明寫「非 Claude Code 環境」，所以那個成績是 Antigravity 的，
   不是 Claude Code 的。Claude Code 能不能用不受影響，能用，只是沒做過同一種測試
3. 「省下大量排版」用錯字。這套流程不處理字體行距，它處理的是文章結構：
   `templates/` 固定了章節順序，`SKILL.md:557` 第 3 站初稿依模板撰寫。
   而結構化不是為了省事，是有目的的：依 `docs/AI可讀性規範的依據.md` 第一節，
   AI 讀文章是切成片段讀，只有被選中的片段進得去，一塊自己站不住的片段就算
   被選中也答不出東西。同一套結構對人也有用，固定的「這篇能回答你」跟文末的
   自我檢查都是為了讓讀者好吸收

## 順帶做的事：index.html 全站清除破折號

`civic-tech-writing-pipeline/SKILL.md:1103` 對這套流程產出的文章訂了「嚴禁使用
破折號」的硬規則，理由是它是 AI 寫作最明顯的破綻之一。網站是這套方法論的門面，
自己卻有 14 處破折號，不一致。2026-09-03 Claire 指示比照同一標準清除，套用
MAPS 原則與 UX Writing 寫法。改法依 SKILL.md 既有的轉換規則：句號拆兩句、
冒號帶出說明、括號補充。README.md 這次不動，範圍只在 index.html。

## 驗收條件

### 一・頁尾「保證」改「實測」
- 1a `index.html` 頁尾不再出現「保證」二字
- 1b 改成講清楚我們實測到哪裡，措辭與全站「實測過／沒實測過」的體例一致
- 1c 不與 FAQ 第二題對 Antigravity 的描述衝突

### 二・工具表實測欄講明證據來源
- 2a Claude Code／Antigravity 那列的實測欄寫明那個成績是 Antigravity 跑的
- 2b 不暗示或明說「Claude Code 不能用」，能用，只是沒做過同一種陌生人測試
- 2c `index.html` 與 `README.md` 兩處一致

### 三・「排版」改為「結構」，並補上目的
- 3a 兩檔「省下大量排版」的「排版」二字都改掉
- 3b `index.html` 補一段講結構化的雙重目的：AI 切片段讀、人一眼看出這篇能不能用
- 3c `README.md` 對應處同步一句，不需要整段搬過去（那裡是開場摘要）
- 3d 不新增没有依據的宣稱（不寫具體秒數、不寫比較級）

### 四・index.html 全站無破折號
- 4a `index.html` 全文 grep 不到「——」或「—」
- 4b 改寫後語意不得偏移，逐處對照原意
- 4c HTML 標籤開閉完整，改寫不得破壞結構

### 五・收尾
- 5a 待辦第二項 B 批三條全部刪除
- 5b 站④：`/code-review` ＋ `acceptance-reviewer`

## 驗證方式

grep 驗 1a、4a；瀏覽器預覽深淺色；`index.html` 與 `README.md` 逐句比對一致；
HTML 標籤解析零錯誤。
