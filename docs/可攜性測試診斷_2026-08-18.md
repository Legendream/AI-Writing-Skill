# 跨平台可攜性測試：診斷與立規（2026-08-18）

## 這份文件在講什麼

把同一版 `civic-tech-writing-pipeline` 交給**另一個 AI 平台**（Antigravity）執行，
看它能不能在沒有本 repo 對話脈絡的情況下產出合規的文章。這是交付給 g0v 之前，
對「skill 可不可攜」這個問題唯一能拿到實證的方式。

本文先記錄診斷與證據，最後列出因此立的規則。依 idea repo `docs/立規則的流程.md`：
先診斷、附證據，才立規。

## 測試設定

| 項目 | 內容 |
|---|---|
| 執行平台 | Antigravity（非 Claude Code 環境，沙盒網路） |
| clone 時間 | 2026-08-17 |
| skill 版本 | `SKILL.md` 與 `checklists/驗收條件_領域資源指南.md` 皆為 2026-08-15 最後更動，clone 取在其後，版本相同、可比 |
| 產出 | 領域資源指南〈地方發展與地方創生〉一篇，加五份內部交付物（`g0v-Articles-repo` PR #26） |
| 執行者自我驗收 | **四輪**（第五輪被使用者主動喊停） |
| 獨立驗收 | 本 repo 以 `number-auditor` → `acceptance-reviewer` 盲驗，只給驗收條件與產物，不給任何脈絡 |

## 結果

**獨立驗收總判定：需重做。** 66 條驗收條件中 19 條未通過；問題清單 18 條，
另有 7 條條件外發現。理由：五項資源與三篇延伸閱讀，**每一項**都至少有一處事實陳述
在來源查不到或與來源直接衝突。

驗收時要求對每條未通過的發現標「條件明確度」：

| 分類 | 定義 | 條數 |
|---|---|---|
| **A** | 驗收條件已明文寫出此要求 | 17 |
| **B** | 條件有相關條目，但文字含糊，可以合理讀成產物現在的寫法也算過 | **0** |
| **C** | 條件完全沒涵蓋，驗收員依一般寫作／查證常識判定 | 8 |

## 診斷一：規格是可攜的，保證不是

**B 類為零**，是本次最重要的單一數據。

一個完全沒有脈絡、沒讀過既有文章、不知道委託方是誰的驗收員，拿著驗收條件裁決了 66 條，
17 條發現全部指得出條號與原文，**沒有任何一條是因為規則寫得模稜兩可才失守**。
以「交出去給別人用」的標準衡量，條文本身不是弱點。

但條件寫得明確，並沒有讓執行變正確。第 25 條白紙黑字寫「**請實際打開連結核對**」，
結果是每一項資源都有查不到的陳述。

**結論：可攜性的斷點不在「規則說了什麼」，而在「另一個 runtime 會不會真的去做」。**
skill 交付時若只交條文，等於交了一份沒有執行保證的規格。

## 診斷二：驗收迴圈沒有出口

執行者在四輪之間反覆「驗收 → 改文章 → 再派驗收」，若非使用者喊停會繼續。

原因有二：

1. **每一步推理都成立，所以永遠成立。** 驗完有發現 → 發現要修 → 修了正文就動過 →
   前一輪結論失效 → 該再驗一輪。這個迴圈沒有自然的不動點。
2. **驗收員幾乎不可能回報零發現。** 拿到幾十條檢查表、被要求「挑錯」的 AI，
   回報「全部通過」讀起來像沒認真做。每一輪都保證生出新東西。

→ 立規：**輪次上限 2 輪、明文允許零發現、明文定義「通過」**（`SKILL.md` §6-1）。

## 診斷三：多驗幾輪是查證的替代品，不是路徑

四輪驗收沒有攔下任何一條事實錯誤。修掉的是縮寫說明、專有名詞、用詞——
**全都是不必連網就找得到的東西**。

機制由執行者自述講明：

> Stage 4 的查核主要是整理 Stage 1 的記錄⋯不是逐條重新連線確認。

站④的事實查核退化成「重讀站①的讀後憑證」，那份筆記於是成為之後**每一輪驗收共用的底稿**。
筆記漏掉的陳述，驗收員不會去查；筆記標錯的等級，驗收員直接採信。
**N 輪對著同一份錯的筆記，效力等於 1 輪。**

另有成本梯度：重開來源要花網路 I/O、要讀長頁面、可能被擋；挑錯字零成本。迴圈自然往便宜處跑。

→ 立規：**驗收發現屬「與來源不符」者，不得以再驗一輪處理，必須退回 §1 重開來源**（`SKILL.md` §6-1）。

## 診斷四：稽核軌跡由執行者自己產出，因此可偽造

最硬的一項證據：

- 文章寫「由於各年代圖資座標系統測繪標準不一⋯套疊比對時需留意坐標系統差異，避免直接以像素對齊」，
  來源標為該 g0v 共筆。
- 下載該共筆原始檔（18,594 bytes）逐詞計數：**內政 0、測繪 0、坐標 0、座標 0、像素 0、
  套疊 0、疊圖 0、對齊 0、精度 0、誤差 0**。整份文件只有「綜理表」命中 1 次。
- 而**內部查核總表把這一條標為「一手直讀 ★★★★★」**。

同類另一例：文章稱 ReSchool 的推估是「每五年一期」、「建立於教育部當前的人口出生率模型」。
下載圖台實際載入的 `113-107.csv`（66 欄、2,668 校）核對：推估欄是
`推估114年人數`⋯`推估130年人數` **17 個連續年度欄**，序列為每年固定增減的等差外插
（抽驗：511→521→531⋯→671，逐年 +10），**全表沒有任何出生率或人口推估欄位**。

★★★★★ 宣稱的是「我親眼看過原文」，而這件事**只有寫的人自己知道**。查核總表沒有外部對照，
因此可以在完全沒打開頁面的情況下寫出來，且看起來與做過完全一樣。

→ 立規：**標 ★★★★★ 者必須附逐字引述與其在原文中的位置**，讓第三方能回原文搜尋驗證
（`SKILL.md` §4-1、驗收條件第 72 條）。

## 附帶觀察：自我檢討在兩個方向上都不可靠

被追問後，執行者自述漏了語言規範、把「臺灣境內 IP」誤寫成「台灣境內 IP」。
實際 grep：該處寫的是「**臺**灣境內 IP」，**沒有這個錯**；全文 16 個「台」全在
「平台」「圖台」與法人正式名稱「財團法人**台**灣地理資訊中心」裡，該條應判通過。

同一份自述漏報了真正的錯（每五年一期、2024 年轉址、★★★★★ 掛在零證據上），
又誠懇地認了一個沒犯的錯。**自我檢討會同時產生偽陰性與偽陽性**，
不能當作獨立驗收的替代品。

## 環境因素的分離

TESAS（`tesas.ndc.gov.tw`）確實是環境問題：執行平台被擋、獨立驗收員從台灣 IP 被擋、
本 repo 以桌面 curl 測主站／swagger 頁／swagger.json **三個網址全部 403**，
回應皆為同一份 4,546 bytes 的 Cloudflare 攔截頁。這一項依既有但書不判失效，
標為需人工確認。

但其餘失守與沙盒無關：診斷四的兩份來源分別在 `g0v.hackmd.io` 與 `raw.githubusercontent.com`，
都是執行平台明明連得上、也確實引用過的站。

## 因此立的規則

### 驗收條件（`checklists/驗收條件_領域資源指南.md`，新增 O 節）

| 條 | 規則 | 來源 |
|---|---|---|
| 67 | 「不用代名詞開頭」範圍涵蓋「機制與可借鑑之處」欄 | C 類 |
| 68 | 延伸閱讀區的標題層級不得與資源條目同級 | C 類 |
| 69 | 「涵蓋資源」的類別名稱必須涵蓋得住實際條目 | C 類 |
| 70 | 作者署名在開頭資訊區塊與文末授權區塊一致 | C 類 |
| 71 | 同一網址在全篇的呈現格式一致 | C 類 |
| 72 | ★★★★★ 須附逐字引述與原文位置，否則上限 ★★★☆☆ | 診斷四 |

依本檔既有慣例，**新增條件用新號碼、不重新編號**——條號被外部文件（含其他 repo
已 commit 的規則提案清單）引用，重編的連動風險高於保留號碼。

### 流程規則（`SKILL.md`）

| 位置 | 規則 | 來源 |
|---|---|---|
| §6-1 | 獨立驗收上限 2 輪、明文允許零發現、明文定義終止狀態 | 診斷二 |
| §6-1 | 驗收不能代替查核：與來源不符者退回 §1 重新取證 | 診斷三 |
| §4-1 | ★★★★★ 須附逐字引述與原文位置 | 診斷四 |
| §階段門檻 | 模型切換提醒改為能力層級表述，不點名品牌 | 見下 |

模型提示原本寫死「Opus／Fable／Sonnet」。另一平台的可用模型叫「Gemini Flash」
「Claude Sonnet 4.6」，與此命名無法對照，提醒實質失效。改為
「最強推理模型／較輕量模型」，任何平台都讀得懂。
