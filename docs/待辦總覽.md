## 兩條維護紀律

1. **做完就刪掉，不是劃掉。** 每件事的來龍去脈已經寫在它自己的驗收文件裡
   （`docs/站①驗收條件_*.md`），完成的項目留在這裡沒有資訊價值，只有噪音。
2. **如果這份檔案變長的速度比變短快**，代表在累積問題而不是解決問題。
   那個訊號比檔案大小本身有意義。

（`docs/` 不隨 skill 的 zip 交付，所以這份檔案不會佔到使用者的 context。）

## 二、獨立驗收累積的既有問題

以下由 `acceptance-reviewer` 扮演陌生讀者時發現，判定為既有問題而未併入當時的 PR。

**A 批・網站與 README 的落差**

- 兩種文體的定義在兩個檔講法不同，可能害讀者選錯
- **六份**交付物沒有一份對應得到「在哪一站產出」。要補的話得先回 `SKILL.md`
  查每份東西在哪一站生出來，是研究不是搬運

**C 批・術語與缺口**

- 「可信程度／查證程度／把握程度」三種叫法指同一件事
- `README.md` 的「`SKILL.md` 不在 repo 根目錄」與另外三處「根目錄有一份」字面相反
- 「哪幾站可以省」表格首欄無表頭

**D 批・技術雜項**

- `.placeholder` 是死 CSS（定義了，零處使用）
- `og:image`／`og:url`／canonical 缺（註解自稱是分享用）
- 下載 zip 按鈕是全頁唯一沒有 `target="_blank"` 的外部連結

## 三、Skill 本體

- **把「素材放 `素材` 資料夾」寫進站①。** 2026-09-03 網站與 README 定了這個慣例，
  但 `SKILL.md` 全文 43 處提到「素材」，沒有一處約定資料夾名稱；站①的開場問題也只問
  「手上已有哪些素材」。目前靠使用者自己跟 AI 講一句才接得起來。**跟瘦身一起做**
- **`SKILL.md` 瘦身。** 2026-09-02 三次成功觸發，**三次都出現「讀取被截斷的中段」**。
  33,042 字元、20,779 個中文字（2026-09-03 量）；官方對 Level 2 的建議是 5k tokens
- **`description` 裡的「知識庫」**（兩處）。**不影響觸發**——驗證有效的是那五個
  主題詞，這兩處一處是用途描述、一處是沒人會講的觸發句。但它**暗示了一個不存在
  的義務**：使用者的文章不一定要放到那裡。正解不是換名字，是拿掉去處：

  > 舊：用於產製公民科技知識庫文章
  > 新：用於把公民科技的實作經驗，寫成別人能照著走的文章

  觸發句可改成真名「為台灣公民科技資料庫貢獻內容」。**跟瘦身一起做**，
  瘦身本來就要動整個檔、本來就要重測，順手改成本為零
- **`styles/default.md`**：把 `claire.md` 裡通用的條目抽出來當自動套用的預設，
  `claire.md` 留作填寫實例。公版不該預設套用作者本人的聲音
- **`§4-1` 一手／二手判準判不穩**：2026-09-02 四次觀察跑出兩種結論
  （★★★★☆ 兩次、★★★★★ 兩次）。判準需要寫得更可判定
