1. **做完就刪掉，不是劃掉。** 每件事的來龍去脈已經寫在它自己的驗收文件裡

2. **如果這份檔案變長的速度比變短快**，代表在累積問題而不是解決問題。
   那個訊號比檔案大小本身有意義。

## 二、獨立驗收累積的既有問題

以下是獨立驗收或事後比對時發現、判定為既有問題而未併入當時 PR 的項目。

**`README.md` 全文清除破折號**

- `SKILL.md:1103` 對這套流程產出的文章訂了「嚴禁使用破折號」的硬規則。`index.html`
  2026-09-03 已清乾淨（現為 0 處），`README.md` 還有 **21 處**（同日 grep 查證），
  當時那批刻意只做網站。轉換法沿用既有規則：句號拆兩句、冒號帶出說明、括號補充。
  改寫後語意不得偏移，要逐處對照原意，所以是文字工不是機械替換

**`index.html` 中文句中換行造成的多餘空格**

- HTML 會把 source 的換行加縮排折疊成一個空格，中文之間本來不該有空格，所以
  「⋯自動生成，\n    這套不適合你」會渲染成「自動生成， 這套不適合你」，句子中間出現肉眼
  可見的空隙。改法是中文句子在 source 裡不斷行，或斷在 HTML 標籤邊界。逐處改要對照原意
- **重測方法**（數字會隨改動變，不要照抄）：瀏覽器開 `index.html`，跑
  `document.querySelectorAll('h2,p,li,td,th')`，對每個元素的 `innerText` 比對
  `/[\u4e00-\u9fff，。：] [\u4e00-\u9fff]/`，數命中的元素個數。2026-09-03 這樣量到 45 個。
  注意「一篇文章 ＋ 一份⋯」這類刻意的空格要人工排除

**`index.html` 開場問題只列了四件裡的三件**

- `SKILL.md:79-88`「開始前必問（已選定類型時）」是四件：主題與素材範圍、手上已有哪些
  素材、有沒有必須包含或避開的內容、掛誰的名字用什麼授權。`index.html:649` 只列前兩件
  加「要寫哪一種文體」，缺後兩件。授權那件在 `SKILL.md` 是特別強調過的（不得沿用
  `examples/` 的署名），網站沒提，讀者不會預期 AI 會問

**分享圖（`og:image`）**

- `index.html` 已有 `og:title`／`og:description`／`og:type`／`og:url`，只缺 `og:image`，
  分享到 Slack／LINE 時沒有預覽圖。**這不是補一行 meta 就好**：全 repo 沒有任何圖檔
  （2026-09-03 以 `git ls-files` 查證），得先決定要不要做一張分享圖、長什麼樣、放哪裡。
  是設計判斷，不跟機械式修正混做
