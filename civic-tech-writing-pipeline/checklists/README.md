# 驗收條件清單：交付前的最後一關

這裡放兩種文體的驗收條件。**寫完文章、交出去之前，用這份清單再檢查一次。**

- [`驗收條件_領域資源指南.md`](驗收條件_領域資源指南.md) ／ 派工用：
  [`驗收條件_領域資源指南_驗收員版.md`](驗收條件_領域資源指南_驗收員版.md)
- [`驗收條件_方法論長文.md`](驗收條件_方法論長文.md) ／ 派工用：
  [`驗收條件_方法論長文_驗收員版.md`](驗收條件_方法論長文_驗收員版.md)

**兩份檔案，用途不同**：帶「_驗收員版」的是**自動產生**的精簡版，濾掉了給規則維護者看的
立規緣由與修訂紀錄，只留驗收員需要的操作型內容（PR #41 的對照實驗顯示，這些緣由對驗收
覆蓋率沒有幫助——精簡版跟完整版打平，見 `docs/實驗_重複規則與驗收覆蓋率.md`）。**實際派工
驗收時用「_驗收員版」**（見下方三種用法），正本留給規則維護者看沿革與判斷該不該改。

正本異動後，執行 `python3 checklists/generate_reviewer_version.py` 重新產生驗收員版，
**不要手動編輯「_驗收員版」檔案**——手改會在下次重新產生時被覆蓋掉。

---

## 為什麼需要這一關（不能靠自評）

`SKILL.md` 已經內建了強制查核關卡，寫作的 AI 會在交付時逐項回報通過與否。
**問題是那份自評不可信。**

真實案例（2026-08-06，第一篇正式交付文章）：交付時的強制關卡自評寫著
「專有名詞首次出現有括號說明 ✅」，實際上 API、XML、Cloudflare、READr、WTO、g0v
**六個都沒有說明**；自評「具體事實均有來源 ✅」，實際上查核總表漏了六類事實。

這不是能力問題。**同一條對話脈絡裡的 AI，會傾向確認自己剛做過的判斷**——
它記得自己「有在注意專有名詞」，於是打了勾，而沒有回頭逐個數。

解法只有一個：**換一雙沒看過產出過程的眼睛。**

---

## 三種用法（照你手上的工具挑一種）

| 你的工具 | 怎麼用 | 效果 |
|---|---|---|
| **Claude Code 等可派子代理的環境** | 派一個驗收代理，**只給它「_驗收員版」清單的檔案路徑＋文章檔案路徑**，不給寫作過程、不給討論脈絡 | 最強：獨立脈絡、能實際開連結查證、能下載檔案抽驗 |
| **ChatGPT／Claude 網頁版等對話工具** | **開一個全新對話**，貼上「_驗收員版」清單的內容＋貼上文章全文，不要貼討論過程 | 中等：一樣有「乾淨眼睛」的效果，查證能力視工具而定 |
| **不用 AI** | 當人工 checklist 逐條打勾（正本、「_驗收員版」皆可，正本多了緣由可幫助人類理解為什麼這樣規定） | 堪用：至少不會漏掉檢查項目 |

**關鍵不在有沒有代理，在有沒有「乾淨的眼睛」。** 開新對話就能拿到大部分效果，
任何人都做得到。

⚠️ 三種用法都有同一條鐵律：**不要把產出過程講給驗收者聽。**
一旦它知道你為什麼那樣寫，它就會開始替你辯護，而不是挑錯。

---

## 派工時要講的四件事

不管用哪種方式，開頭都要交代：

1. **產物在哪**：檔案路徑或全文
2. **這是定稿還是草稿**：定稿的話，任何留空記號、待補標記都算缺陷
3. **驗證環境**：如果文章引用的網站可能有地區限制（例如台灣政府網站常阻擋境外 IP），
   要請驗收者說明它從哪裡連線。**連不上不等於連結失效**，這種情況應回報
   「無法從此處驗證，需人工確認」，不可判定為死連結
4. **有沒有「人工核准例外」檔案**：若 `_驗收紀錄/<篇名>_人工核准例外.md` 存在，
   一併給驗收員，並明講「對照表裡列到的條目，通過／不通過的事實照樣如實回報，
   但不列入問題清單」（見 `references/交付與格式.md`「人工核准的例外，要記下來」）。
   沒有這份檔案就照條件字面判定，不要自己假設哪條「應該可以」

## 收到結果之後

驗收結果分成兩種，處理方式不同：

- **這一篇的個別錯誤** → 修完就結束
- **skill 沒防住的「類型」** → 這才有長期價值，且**不能只寫下來就算了**

第二種是這套 skill 進化的主要來源，但「寫成規則提案」本身如果沒有牙齒，會靜靜蒸發——
真實案例：一條「資源網站的 `/about` 是必讀素材」的建議被完整記在查核總表裡，
兩天內沒有任何機制檢查它有沒有真的搬進 `SKILL.md`，直到下次盤點才發現從沒被搬過。

**所以「skill 沒防住的類型」要走這三步，不是寫完就結束**：

1. **記進本篇的查核總表**，格式見 `references/交付與格式.md`，牙齒規則見 `SKILL.md` §6-5
2. **狀態標「未搬運」**，這是誠實的起點，不是問題
3. **真的搬進 `SKILL.md`、`templates/` 或這份 `checklists/`**，並把狀態改成
   「已開 PR #N」或「已併入」——只有這一步才算完成，光是把發現寫進查核總表
   不算數。搬去哪個檔案、要不要另開一份 `docs/` 的診斷文件，視發現的份量而定；
   單一小發現可以直接改規則，跨多篇才浮現的模式才需要獨立診斷文件

`SKILL.md` 現在那些查核規則，每一條都是從一次具體犯錯長出來的——但只有真的被搬過去
的那些才算數，躺在某篇文章查核總表裡的提案不算。
